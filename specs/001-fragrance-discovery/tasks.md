```text
Setup → Foundation → US1 discovery slice → Checkpoint A
                                           ↓
                         CI freshness/build → First Vercel deployment
                                           ↓
                                Real-phone slice review
                                           ↓
                             US1 detail continuation → US1 accepted
                                           ↓
                            US2 recovery + minimum editor
                                           ↓
                               US4 P1 integration gate
                                           ↓
                            US3 P2 refinement + US4 recheck
                                           ↓
              Visual/performance/device refinement → final release → demo
```

US1 and US2 are both P1; US4 is also P1 and precedes P2 refinement as a dedicated gate. US4 requirements apply from foundation onward and its final all-story acceptance depends on the US3 recheck. US2 editing recovery uses the minimum editor required by its own acceptance; US3 adds full refinement comparison/choreography. Full US1 independently exercises details; its initial deployable slice intentionally precedes details per plan. Tests for each story can use isolated controlled fixtures, but shared production integration follows this graph.

Each checkpoint requires meaningful automated checks plus manual accessibility/reduced-motion/mobile review of the affected flow. Record observed evidence and resolve violations before marking tasks complete. A real device cannot be substituted by emulation. Deployment is an explicit implementation milestone, not an action authorized by generating this document.

## Implementation strategy

1. Deliver the smallest complete **discovery slice** with real data, deterministic evidence, premium mobile compositions and working motion/reduced motion. This is the initial deployment scope, not permission to omit the remaining approved stories.
2. Deploy immediately after its checks and use real-phone feedback while completing US1 details, US2 recovery, US4 integration and US3 refinement. Keep offline data checks in development/CI and static npm tooling on Vercel.
3. Validate every increment with keyboard, reduced motion and mobile checks. Complete all screens and motion variants before final cross-cutting refinement; retain readable truthful content throughout choreography.
4. Finish with measured responsiveness/mobile motion, final deployment verification and the actual portrait demo. Usability observations remain empirical work; report only collected evidence.
