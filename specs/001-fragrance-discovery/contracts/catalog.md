# Catalog Preparation and Loading Contract

## Source and invocation

Planned command: `python scripts/prepare_catalog.py --input data/fragrances.csv --taxonomy data/taxonomy.json --output src/data/catalog.json`; optional `--check` validates and compares expected generated bytes without changing output. These interfaces are designs, not commands available yet.

CSV headers: `id,name,price,currency,image_src,image_alt,key_notes,intensity,feeling_tags,occasion_tags,product_path`. UTF-8, RFC-style quoting. `price` is a decimal USD string (e.g. `49.99`); `key_notes` is a JSON array of named notes and category arrays inside a quoted CSV cell. Tag cells are JSON arrays or blank (unspecified). JSON `[]` means known empty. This avoids ambiguous separators inside note names.

Read with Pandas using string dtype and automatic NA conversion disabled; parse nested JSON explicitly. Trim outer whitespace but do not coerce invalid enum values, currency, missing required values or numeric identities. Parse price using Decimal and accept only unsigned ordinary decimal notation with at most two fractional digits; reject negatives, NaN, Infinity, exponent syntax and values outside safe integer cents. Zero is valid. Never pass prices through binary floating point.

## Validation and duplicates

1. Validate file readability, encoding, exact required header presence and CSV structure. Reject duplicate headers and malformed CSV with a file-level error.
2. Parse/normalize rows and retain identity references even when another field is invalid. Validate required fields, note/category associations, vocabulary, intensity, USD price, local image path and product destination. Check referenced local asset existence at preparation time, reject traversal/external references, and report required alt-text omissions. Meaningfulness and visual correspondence require editorial review.
3. Group by stable identity before eligibility filtering. Canonically identical parsed records collapse to one, with duplicate diagnostics. Any disagreement within one identity excludes the entire group, including a valid record paired with a malformed conflicting row. Unknown values are not equal to explicit empty tags. Normalize order-insensitive sets before duplicate comparison.
4. Exclude invalid identities; retain otherwise valid products with unknown feeling/occasion tags and record that limitation. Serialize eligible products sorted by ASCII ID, sort set-valued arrays and issue diagnostics consistently; preserve intentional named-note display order.
5. Produce no output replacement on validation failure. Use an atomic replacement only after a successful validation. Exit 0 for a clean source, 1 for invalid rows, identity conflicts, schema/parse failures or unusable nonempty source, and 2 for invocation errors. Exclusions are described in diagnostics but the ordinary strict command fails rather than publishing a newly degraded artifact. An explicit `--allow-exclusions` fixture/demo command may emit quarantined results with diagnostics; it never admits excluded rows. Unknown optional tags and identical deduplication are warnings and do not fail strict validation.

A header-only source is a valid empty catalog. Development fixtures separately exercise unreadable/wholly unusable data. Required assets are authored dependencies; preparation cannot invent image descriptions, tags or claims.

## Browser boundary

Expose `src/data/catalog.json` as a Vite asset URL using a `?url` import, so development and built preview both serve the same versioned static document. Fetch that local generated JSON on demand with a finite 5-second timeout and retry support; validate its version, envelope and product fields defensively in TypeScript. Recompute duplicate handling, exclusions and unknown evidence rather than trusting malformed data. A valid catalog with zero eligible matches produces empty; unreadable/malformed envelope or nonempty catalog with no usable records produces error. A 5-second timeout bounds failure recovery on stalled requests; the 1-second performance target applies under the defined healthy static-server conditions, not induced outages.

Carry preparation diagnostics into runtime limitation disclosure. Never expose raw diagnostic dumps as shopper copy: explain that some catalog information is unavailable; unknown evidence is labeled per product. Build/check commands must reject stale generated JSON. No runtime Python, Pandas, database, external data service or API key.
