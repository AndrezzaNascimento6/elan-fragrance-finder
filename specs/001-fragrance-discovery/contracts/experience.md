# Experience and Accessibility Contract

## Presentation

Use a fictional premium Élan beauty identity with predominantly black/warm-black ground, high-contrast off-white typography, thin elegant serif display headings and restrained champagne/warm metallic accents, generous whitespace and consistent local fragrance photography/illustration. Lead results with product imagery and preference evidence, then supporting alternatives; avoid a dashboard grid shell. Delicate handwritten/script accents are decorative only, with no essential words or accessible information depending on them. Use large art-directed bottle, glass, flower, ingredient, fabric and atmospheric light/shadow imagery, generous negative space and few visible elements. Avoid ecommerce/dashboard grids, SaaS cards and neon AI styling. Atmospheric imagery must not imply unsupported product ingredients. All three results retain equivalent required information and usable links. Local fonts have fallbacks, imagery has reserved aspect ratios, responsive sources and meaningful alt text. Failed images show a labeled unavailable-image fallback, not an invented substitute product. Product details only repeat catalog-backed identity, image, notes, intensity, tags and price; disclose fictional/demo status, no checkout or fabricated longevity/reviews.

## State and interaction obligations

- Intro identifies fictional preference-based support, five questions and lack of a satisfaction guarantee.
- Questions appear in FR-002 order, each a fieldset/legend with native single-select radios, visible selection mark and “Question N of 5.” Continue without selection stays in place, links inline error to the group and moves focus predictably to the unanswered group. Back preserves selections.
- Submission/apply immediately shows processing status, snapshots preferences and loads/ranks without an artificial pause. Announce completion with a polite live region; use a separate alert for actionable errors. A fast run may skip the sensory interlude entirely; it must never wait for choreography.
- Results show up to three products, required FR-008 fields, exact/partial N-of-4 wording, four-dimensional evidence, separate USD budget compliance, tie disclosure, all five active preferences and editing controls. Fewer than three yields an honest count explanation. Unknown/excluded catalog information yields a limitation notice.
- Empty shows no product fillers, all active preferences and individual editing actions. Error retains answers and offers retry and edit; previous recommendations are hidden. Retry uses latest applied values. Only the current request may complete.
- Inline edit uses a draft radio group with Apply and Cancel. Opening focuses its legend/first relevant control; cancel restores the invoking control and original result. Apply commits one field, preserves four others, and announces the changed preference plus inclusion/order/evidence outcome. Applying the existing value closes without claiming a change. Restoring an answer is supported with the same editor.
- Detail is a hash destination with a labeled return link and native browser navigation. Return restores finder state and focus to the originating product link where possible. Invalid destinations expose a readable not-found message and return control.

## Accessibility and responsive behavior

Use semantic main/header/nav, hierarchical headings, lists for recommendations, links for destinations and buttons for actions. Focus new question/result/error headings when replacing the main view; inline updates use announcements without unnecessary focus stealing. Editor controls remain inline to avoid modal focus complexity. Use `aria-busy` for the changing results region and concise status text; do not announce all result prose repeatedly. Preserve logical DOM order on desktop and mobile.

Verify text contrast ≥4.5:1 (large text ≥3:1), control/focus contrast ≥3:1; visible focus must not be obscured. Use comfortably sized touch controls (design target 44 CSS px), readable line lengths, 200% text zoom and reflow at 320 CSS px/400% desktop zoom without horizontal page scroll. Selection and match status use text/icons as well as color. No hover-only information. Respect `prefers-reduced-motion` through the explicit alternative choreography below. State, evidence and actions never depend on animation completion.

Review against [WCAG 2.2](https://www.w3.org/TR/WCAG22/), including non-text content, keyboard, focus, reflow and status messages. Automated scans supplement manual keyboard, screen-reader and visual review; they do not establish compliance alone.

## Mobile composition and browsing

Design portrait mobile at 390×844 first, then verify 320 CSS px reflow, short-height and landscape layouts. Intro reserves a portrait product/ingredient focal point with a legible heading and readily available Start. Questions place progress, one heading and stacked touch-friendly options in a clear reading order; Back/Continue remain reachable with natural scrolling. Selection is explicit and does not auto-advance.

Results open on the primary bottle composition with name, N-of-4 match, price and intensity close together. Follow with key notes, all four evidence dimensions (including mismatches/unknowns), budget compliance, details and active preferences/editing. Browse alternatives in the same vertical editorial sequence, using labeled in-page links such as “View recommendation 2 of 3” and a return to the primary result. Do not require swipe, hover, auto-advance or horizontal page scroll. All results have equivalent information and no evidence is hover-only or available only after animation. Maintain truthful tie language despite primary visual prominence.

Inline editing expands at its invoking preference, scrolls into view only as necessary and keeps Apply/Cancel visible in the reading flow. Preserve other answers and restore meaningful focus after commit/cancel. Desktop may place imagery beside text without changing semantic order. Mobile crops protect the bottle and text separately; do not overlay essential text on uncontrolled image contrast. Scale headings without clipping, use readable body text, safe-area padding and dynamic viewport sizing with content allowed to grow; sticky controls must never cover content or focus. No mandatory full-viewport panel height.

## Motion contract

Durations below are initial design budgets for refinement, not deliberate waits or measured results. Common short feedback is 100–180 ms, spatial transitions 200–350 ms, optional hero accents 450–700 ms. Intro is interruptible and Start is available immediately. Results/evidence and controls paint promptly within the plan's latency targets; optional dramatic duration applies to decorative imagery only, while meaningful text remains readable. Never stage essential evidence at opacity zero awaiting a long stagger.

| State | Standard motion | Reduced-motion equivalent |
| --- | --- | --- |
| Intro | Layered heading entrance with restrained translation; bottle/light reveal and a bounded atmospheric depth/blur accent. Start leads directly into discovery. No required autoplay video or ongoing decorative loop. | Static art-directed image and complete heading; optional short opacity fade, immediate Start. No parallax, zoom, travel, blur animation or continuous movement. |
| Answer selection | Visible mark/text appears immediately; brief outline/background emphasis and small local scale cue. | Immediate mark/text with optional brief color/opacity transition; no scale. |
| Question change | Consistent short forward/back translation plus opacity, with coordinated image/type change. Keep progress anchored and prevent duplicate active question controls. | Replace in place or fade ≤120 ms; same heading focus, progress and preserved selection. |
| Actual processing | Current selected words and a small bounded ingredient/light composition transform while work is pending, accompanied by explicit processing text. Stop immediately on completion/error; do not make words into unsupported product evidence. | Static selected words and explicit status; no particles, atmospheric loop, blur or travel. Fast results may bypass this state visually in either mode. |
| First results | Primary bottle entrance is the visual peak; restrained stagger of supporting accents around already readable identity, price, intensity and evidence. | Immediate complete recommendation with optional ≤120 ms fade; identical evidence and hierarchy. |
| Browse alternatives | User-directed in-page navigation with a bounded product image/text reveal. No autoplay. | Immediate scroll/navigation and optional short fade; disable smooth scrolling. |
| Applied edit | Immediately update the preference label, show current processing status, then reveal actual product inclusion/order/evidence changes. Use stable product IDs and short bounded movement/fade for current results; highlight affected evidence without relying on color. | Immediate label/status and new results; optional short fade/emphasis, with identical text change summary. No reorder travel or zoom. |

When products/order remain the same, explicitly name the applied preference and explain the evidence-based reason: affected match evidence may change without changing the top eligible products, or the catalog evidence may be unaffected. Preserve missing-data distinctions. If evidence also stays the same, say so truthfully. Reapplying an existing value closes the editor without a recalculation claim or staged transformation. Changed and unchanged paths both provide persistent readable summaries and concise live announcements; animation alone never signals success.

Commit current application state independently of animation. Interrupt obsolete sequences on new actions; current request tokens govern completion. During pending/failed edits hide old recommendations as specified above; do not retain an old animated card as an apparently current recommendation. Exiting decorative layers must be inert, hidden from assistive technology and unable to trap focus. New heading focus and status updates occur on state commitment, never on an animation callback. Inline updates retain appropriate editor/return-control focus without repeatedly announcing entire recommendations.

Use MotionConfig's user policy plus useReducedMotion for custom variants and CSS `prefers-reduced-motion` for native effects. React to setting changes mid-visit. Reduced motion removes parallax, large zooms, long travel, continuous decoration and animated blur; retain only helpful short fades/emphasis. Keep essential text as whole semantic words/headings, with decorative split-letter duplicates hidden from assistive technology. No script in essential UI, evidence or status. No flashing/strobing effects.

## Mobile motion quality

Prefer transform/opacity with few composited layers; bake light/texture into responsive static assets rather than animating expensive full-screen blur/shadow/filter effects. Reserve image aspect ratios and use font fallbacks so layout does not jump. Stop offscreen/hidden animation and avoid repeated scroll-triggered entrances. Motion never blocks touch, keyboard input, scrolling or current state; imagery/font readiness never gates results.

Validate a production build on an actual typical mobile device, recording model, OS, browser and refresh rate alongside emulated conditions. Profile the intro, question changes, first results, alternative browsing and rapid/cancelled/unchanged edits; record lightweight findings on visible stutter, long tasks and response measurements; keep traces and recordings outside Git. Simplify expensive effects when they cause noticeable jank. Repeat in reduced motion, including changing that setting during the visit. A polished recording must demonstrate the real working flow and must not require injected delays to capture processing.
